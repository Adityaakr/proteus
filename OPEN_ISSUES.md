# OPEN_ISSUES

- **Testnet proof is self-run.** The loop ran on Arc testnet with our own funded key as buyer (`docs/acceptance-report.md`). It is proof of the mechanism, not traction. Public RPC nodes behind the load balancer can lag; the reconciler now re-scans a 30-block overlap and reads balances at the scanned head.
- **Circle relayer unverified.** `createContractExecutionTransaction` with `callData` on `ARC-TESTNET` is implemented from the installed SDK types but has not been executed. Until it runs, Circle usage must be reported as "integrated, not yet exercised". The viem relayer is the verified path.
- **Seller signer is server-held for the sandbox seller.** This is the "owner-approved, narrowly delegated seller signer" the spec allows. A real seller should sign Terms from their own wallet (SIWE console login + browser signing), which is not built.
- **Permit / EIP-3009 on Arc USDC unverified.** Funding uses `approve` + `transferFrom` (two buyer transactions). Verify `permit` support on `0x3600…0000` to collapse to one.
- **Grace window vs late receipts.** Settlement after `end + grace` reverts by design; a receipt submitted late is not settleable. Sellers should settle before the window closes. Documented in `docs/settlement-model.md`.
- **Reconciler scans the last 5,000 blocks on first run.** Deals funded earlier than that before the API first saw them would need a manual backfill.
- **Rule-based extraction is regex based.** Numbers in unusual phrasing may be missed; the agent then asks a clarifying question rather than guessing.
- **Rate limiting is partial and per instance.** Invite redemption and the admin routes are limited in memory (8 attempts per IP and per account per 10 minutes, 20 for admin); the counters reset on restart and are not shared across replicas. Other public routes are still unlimited.
- **Blocklisted payee DoS.** If a seller payee is blocklisted on Arc, settlement reverts (Arc transfer rules). The arbiter path can route funds to the buyer; no seller-side recovery exists.
- **Owner is the arbiter.** `Deploy.s.sol` defaults the arbiter to the deployer, so on the testnet deployment the owner key decides the split of any disputed deal. Set `ESCROW_ARBITER` to a separate party before anything that matters.
- **Deal routes are capability-id gated.** `GET /deals/:id` returns the one-time API key to whoever knows the deal id; ids are random and unguessable, but there is no login check, by design for agent access. Tie the read to a buyer wallet signature before public hosting.
- **Figure guard limits.** The OpenRouter guard catches dollar amounts, percentages, suffixed and multi-digit numbers; spelled-out numbers pass. Prices are never decided by the reply, so this is a wording control, not a money control.
- **Circle tokens live in the browser.** With Circle sign-in, the Circle user token and encryption key sit in local storage so the web SDK can run challenges; Circle recommends HttpOnly cookies. Fine on testnet; move them behind a cookie plus a server-side exchange before mainnet.
- **Email OTP depends on SMTP in the Circle console.** Circle sends no mail itself; until SMTP is configured there, email sign-in answers with Circle's own error and only wallet sign-in works.
